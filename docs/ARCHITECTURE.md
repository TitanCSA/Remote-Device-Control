# Direct streaming architecture

The target installs one LocalSystem wrapper service, a managed Sunshine engine and the unchanged Vdevice demo. The controlling PC runs a portable Win32/Direct2D application using the actual `moonlight-common-c` library. No application component calls a central relay, licensing site or Internet host directory.

The wrapper waits for an unlocked signed-in console, launches a visible indicator under that user's token, then starts its protected engine under a system token assigned to the console session. A kill-on-close job ties each child to the service. Lock, logoff, session change and service shutdown stop the engine. The normal-user indicator has an authenticated local pipe bound to the exact launched PID/session and SCM-owned server; it sends only readiness, heartbeat and disconnect messages. It has no privileged command, driver handle, capture or input interface.

Protected settings are DPAPI-encrypted and stored under SYSTEM/Administrators-only ACLs. Engine configuration, certificates and state are similarly protected. The web configuration UI is disabled; the only application entry is the managed Desktop target, with no arbitrary launch command. The per-process access policy is passed only in the privileged child's environment, not its command line or the user's indicator environment.

A private connection code contains the address, GameStream base port, server certificate pin and random access secret. For a manually entered code-free address, a credential-free TLS probe exposes the fingerprint for user confirmation before any secret is sent. LAN discovery is optional and nonce-bound; it is not an out-of-band identity authority.

Initial HTTPS `/rdc-pair` authorization binds a bounded RSA client certificate after the code policy is checked. The native viewer verifies the server pin first. All other GameStream HTTPS routes require an exact registered client leaf certificate. Legacy PIN pairing is disabled. Pairing state is cleared at engine start so previously public clients cannot retain access after the policy is changed. These application-specific authorization steps precede the actual upstream HTTPS/RTSP/GameStream streaming protocol.

Launch reserves one target slot. Optional local approval applies to every connection, including an already registered client, before virtual-device creation. The active slot is bound to the exact client identity; another client's cancel/resume cannot take it over. Unused reservations expire. The engine creates an NKRO keyboard, absolute mouse and relative mouse through Vdevice only after permission. Startup waits for the exact newly owned sources to appear in Windows Raw Input and for neutral keyboard/relative-mouse reports to be consumed. It introduces no fixed warmup and does not move the absolute pointer during preparation. Relative input uses its own HID report rather than cursor-position approximation.

Video uses Sunshine H.264 capture/encoding and Moonlight RTP/UDP, FEC and recovery. LAN/WAN stream encryption is required. The viewer's pull-renderer worker owns Media Foundation/D3D11 decoder state; bounded complete access units are consumed from the upstream queue. Decoder errors request a new IDR frame. The UI retains the latest owned BGRA frame, avoiding UI work on the network thread. Current hardware decode includes GPU conversion/readback, not zero-copy presentation.

The input/control transport is upstream Moonlight ENet with encryption. Key/button order is preserved by that channel; pointer movement may be coalesced. All input is validated and translated to Vdevice HID reports. Disconnect, desktop loss, demo expiry and input failure release held input and destroy only the owned virtual devices.

The managed engine is based on pinned Sunshine v2025.924.154138, with explicit upstream certificate-validation, control-packet bounds and input-size fixes backported, plus the managed authorization/Vdevice backend. Exact source pins, patches and build instructions are provided under `ThirdParty/` and `Tools/`.

Direct Internet access is opt-in and requires actual reachability. UPnP is a convenience, not a relay or CGNAT bypass. Discovery stays local and is never published to an Internet directory.
